# 採用可否の判定基準 (triage)

目的: 「**企業が実データ・実サービス・実業務にデータサイエンス/機械学習/最適化等を適用した事例**」だけを残す。

## 採用する(すべて満たす)

1. **企業が主体**: 著者/執筆者の所属に企業を含む(大学との共同研究も可。`collab_academia: true`)。
2. **実運用への適用がある**: 自社(または顧客)の実データ・実サービス・実業務での適用が書かれている。
   - 例: 本番導入、オンライン実験(A/Bテスト)、実データでの検証と運用上の知見、導入後の効果測定
3. **技術的な中身がある**: 課題・手法・結果のいずれかが具体的に説明されている。

## 不採用にする

- 理論・ベンチマーク中心で、実サービス/実データへの適用がない論文
- 製品発表、採用告知、イベント告知、カンファレンス参加レポートのみ
- 入門解説・チュートリアル・ツール紹介(自社の事例が主題でないもの)
- 純粋なインフラ/開発手法の記事(ML/データ分析/最適化が主題でないもの)
- 本文が確認できず、title/summary からも適用の有無を判断できない(→ 理由 `insufficient-info`)
- 情報源の `filter_hint` に反するもの

## 境界ケースの扱い

| ケース | 判断 |
|---|---|
| 企業の研究所による論文だが、データは公開ベンチのみ | 不採用(`no-real-world-application`) |
| 公開データ+自社データの両方で評価 | 採用 |
| LLM活用の社内ツール事例(業務効率化) | 実運用なら採用 |
| 大学所属のみで、謝辞にだけ企業協力 | 不採用(`no-company-author`) |

## 出力

- 採用/不採用、理由コード(下記)、確信度(0〜1)を決める。
- 理由コード: `no-real-world-application` / `no-company-author` / `not-technical` / `off-topic` / `insufficient-info` / `duplicate-of-existing`
- `data/rejected.jsonl` の `reason` には「コード: 一言の説明」を書く。
